# VIPER

VIPER applies strong role separation to an iOS feature through View, Interactor,
Presenter, Entity, and Router components. It is role-specific depth: learn it for teams
that use it or interviews that name it, not as a default for every app.

## Learning Path

1. [View, Interactor, Presenter, Entity, and Router](view-interactor-presenter-entity-and-router/README.md)
2. [Module Assembly, Routing, and Data Handoff](module-assembly-routing-and-data-handoff/README.md)
3. [Testability, Complexity, and Adoption](testability-complexity-and-adoption/README.md)

## Preparation Paths

- **Rapid review:** Read the three overviews and learn the dependency flow and main costs.
- **Standard preparation:** Complete all bundles when the target team uses VIPER or asks
  about highly separated UIKit feature modules.
- **Role-specific depth:** Focus on module contracts, routing ownership, code generation,
  and incremental adoption in a large existing app.
